## 1. Test Fixes: PDF Text Extraction Validation

### Problem
Two test failures were reported on macOS:
- `test_full_pdf_pipeline`: Empty DataFrame returned (no keywords extracted)
- `test_convert_valid_pdf`: Empty text content extracted from PDF

### Root Cause
PDFs from `../amilib` or system PDFs may not have extractable text (image-based PDFs or PDFs with text in formats PyPDF2 cannot extract).

### Solution Implemented
Added validation function `_has_extractable_text()` in `test/conftest.py` that:
- Checks if PDFs have extractable text content (minimum 50 characters)
- Validates first 3 pages using PyPDF2
- Returns `False` if extraction fails or insufficient text

### Changes Made
1. **New Function**: `_has_extractable_text(pdf_path, min_text_length=50)`
   - Validates PDFs have extractable text before use in tests
   - Checks first 3 pages for text content

2. **Updated Fixtures**:
   - `_find_amilib_pdfs()`: Now filters to only return PDFs with extractable text
   - `_find_system_pdf()`: Only returns system PDFs with extractable text
   - `sample_pdf_path`: Validates extractable text before using existing PDF
   - `sample_pdf_paths`: Validates extractable text for each PDF

### Impact
- Tests now use only PDFs with extractable text, ensuring valid test data
- Fallback to created sample PDF if no extractable PDFs found
- Prevents empty text extraction and empty keyword DataFrames

## 2. CLI Architecture Decision

### Current State
txt2phrases uses argparse subcommands:
- `txt2phrases pdf2txt`
- `txt2phrases html2txt`
- `txt2phrases keyphrases`
- `txt2phrases auto`

### Decision
**Keep the current subcommand system** - no changes needed.

### Rationale
- Single command namespace (`txt2phrases <command>`)
- Consistent help system
- Easier to discover commands
- Follows common CLI patterns (git, docker, kubectl)
- Less namespace pollution
- Easier maintenance

## 3. Proposed Feature: Merge Keyphrase CSV Files

### Requirement
Add functionality to merge multiple keyphrase CSV files, aggregating counts for duplicate keywords.

### Proposed Strategy

#### New CLI Subcommand: `merge`
```bash
txt2phrases merge -i keywords_folder/ -o merged_keywords.csv
txt2phrases merge -i file1.csv file2.csv file3.csv -o merged_keywords.csv
txt2phrases merge -i keywords_folder/ -o merged_keywords.csv --top-n 500
```

#### Implementation Plan

1. **New Module**: `txt2phrases/merge.py`
   - Function: `merge_keyphrase_csvs(input_paths, output_path, top_n=None, sort_by='count')`
   - Handles single file, multiple files, or directory input
   - Aggregates counts for duplicate keywords
   - Optional top-N filtering and sorting

2. **CLI Integration**: Add `merge` subparser to `txt2phrases/cli.py`
   - Arguments:
     - `-i, --input`: Input CSV file(s) or directory
     - `-o, --output`: Output CSV file path
     - `-n, --top-n`: Optional top N keywords (default: all)
     - `--sort-by`: Sort by 'count' (default) or 'keyword'

3. **Algorithm**:
   - Collect all CSV files from input
   - Load and validate structure (`keyword`, `count` columns)
   - Aggregate counts using `Counter` or `groupby().sum()`
   - Sort by count (descending) or keyword (ascending)
   - Apply top-N filter if specified
   - Write merged CSV

4. **Testing**:
   - Unit tests for merge functionality
   - CLI tests for merge subcommand
   - Edge case handling (empty files, missing columns, etc.)

#### Example Usage
```bash
# Merge all CSV files in a directory
txt2phrases merge -i keywords/ -o merged_keywords.csv

# Merge specific files
txt2phrases merge -i file1_keywords.csv file2_keywords.csv -o merged.csv

# Merge with top 100 keywords
txt2phrases merge -i keywords/ -o top100.csv --top-n 100
```

#### Integration with Existing Workflow
```bash
# Current workflow
txt2phrases keyphrases -i texts/ -o keywords/ -n 1000

# New workflow with merge
txt2phrases keyphrases -i texts/ -o keywords/ -n 1000
txt2phrases merge -i keywords/ -o merged_keywords.csv --top-n 500
```
